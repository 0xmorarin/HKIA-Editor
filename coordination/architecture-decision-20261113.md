Rust/Svelte are NOT Beta prerequisites. Preserve UI, image pipeline, local-only processing, operation-scoped capability gating, independent QA and rollback. - Formal HKIA Editor release: REQUIRED Svelte + TypeScript frontend, Vite, Rust save core compiled to WebAssembly, actual Web Worker and single Worker-owned ProductSession. No JS Writer fallback or permanent second Writer in the formal product. JS may remain the Beta maintenance/reference/test implementation outside the formal production write path.
- Formal feature scope and existing release acceptance do not shrink: valid Achievements and Collections operations, individual/bulk, mandatory causal updates, exact data preservation, independent reparse/diff, verified separate output, actual browser and required irreducible game persistence evidence. Unsupported scope fails closed. Actual deployment, flag changes and formal promotion need their existing independent approvals; this ADR grants none.
- The earlier same-source/same-UI/same-assets Beta rule means real functional product lineage, not a throwaway demo. The independently accepted migration is an explicit exception to literal unchanged JS source at formal promotion. Each fixed release candidate has identical tested and distributed implementation, UI/assets and artifact. Preserve accepted behavior and images through migration. Do not infer JS test PASS on Rust or Svelte.
