## Core contract and capacity
Input -> Validate -> Decode -> Index -> Plan -> Diff -> Apply -> Encode -> Reparse -> Verify -> Export. SaveGameV2/ZIP/LZ4/Native MessagePack, versioned schema, Hash128, exact i64/u64, byte-range/lazy indexing, opaque/token preservation, typed commands/results, single Worker-owned ProductSession, revision/CAS/generation, atomic cross-model edits, Undo/Redo/Reset, original backup and verified edited copy, bounded resource budgets. No full decoded JSON or repeated whole-save transfer across UI/WASM. Decimal strings or exact BigInt at JS boundary, never lossy Number.

Current V17 source: src/save.js MAX_INPUT=25 MiB, MAX_OUTPUT=45 MiB, blocks 4096, block bytes 65536; native schema reader 1M container elements, 2M logical nodes, depth 80. Retain existing defenses until measured replacement budget. Owner design targets: 64 MiB decoded normal, 128 MiB stress, 2M documents; compare 1/5/10/25/45 MiB, JS Worker vs Rust WASM Worker under real browser. Targets not measured or guaranteed.
